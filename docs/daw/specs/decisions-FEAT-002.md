# Decisiones de FEAT-002

Decisiones tomadas durante CODE que no están en la spec aprobada. Formato: decisión — quién la aprobó — fecha — bloque.

## Block 1 — Bloqueo de red en las pruebas unitarias

- Quedan fuera del bloqueo, como límite conocido: las consultas DNS directas (`dns.lookup`, `dns.resolve*`), los `worker_threads` y procesos hijos que lance una prueba, las redirecciones internas del XHR síncrono de jsdom y los sockets creados con `new dgram.Socket({ lookup })` sin pasar por `createSocket`. Están declarados en la cabecera de `src/bloqueoRedPruebas.js`. ADR-002 menciona solo los procesos hijos; este registro completa la lista. — el usuario — 2026-11-10 — Block 1
- Cuarta ronda de corrección autorizada como excepción, solo para el puerto escrito como texto no canónico en `net.Socket#connect(puerto, host)`. — el usuario — 2026-11-10 — Block 1
- Quinta ronda de corrección autorizada como excepción, solo para dos huecos: un arreglo que no es el normalizado de `net.connect` y la IP de loopback con ceros a la izquierda junto con un `lookup` propio. Desde esa ronda, la revisión del bloque bloquea solo los caminos por los que el código normal podría salir sin querer; los caminos armados a propósito para evadir el bloqueo se anotan aquí como límite conocido. — el usuario — 2026-11-10 — Block 1
- Límite conocido, según el criterio anterior: un arreglo armado a mano con un `Symbol('normalizedArgs')` propio y `host`/`port` propios engaña a `EsArregloNormalizado`. Requiere construirlo a propósito; ningún uso normal de `net`, `tls`, `http` o `fetch` lo produce. — criterio aprobado por el usuario; registrado por la revisión de spec — 2026-11-10 — Block 1
- Nuevo export `ComprobarBloqueoTrasPrueba()`, que la spec no lista. Hace las dos comprobaciones del `afterEach` en el orden de la spec y vacía el registro en el mismo error, para que falle la prueba que desinstaló el bloqueo y no la siguiente. — aceptado por la revisión de spec (daw-module-verifier); mostrado al usuario — 2026-11-10 — Block 1
- El XHR se trata como síncrono con cualquier tercer argumento falso (`length >= 3 && !argumentos[2]`), no solo con `false`, porque jsdom lo convierte a booleano. — corrección pedida por la revisión de arquitectura; mostrado al usuario — 2026-11-10 — Block 1
- `dgram.createSocket` también se parchea: un socket con `lookup` propio solo acepta destinos que sean IP literal de loopback, y su `lookup` queda envuelto para que no devuelva direcciones externas. — corrección pedida por la revisión de arquitectura; mostrado al usuario — 2026-11-10 — Block 1
- El estado del bloqueo (parches, originales y registro) se guarda en `process[Symbol.for(...)]`, compartido por los archivos de un mismo proceso de Vitest. Un intento asíncrono tardío de un archivo se atribuye a la prueba en curso de otro archivo del mismo proceso. — supuesto del implementador, aceptado por las dos revisiones; mostrado al usuario — 2026-11-10 — Block 1
- Si una prueba desinstala el bloqueo, se reinstala antes de lanzar el error, para que las pruebas siguientes sigan bloqueadas. — supuesto del implementador, aceptado por las dos revisiones; mostrado al usuario — 2026-11-10 — Block 1
- Una URL de XHR que no se puede leer se rechaza como externa y se registra con el marcador `url-ilegible`. Los hosts se comparan sin distinguir mayúsculas y sin los corchetes de IPv6. — supuesto del implementador, aceptado por las dos revisiones; mostrado al usuario — 2026-11-10 — Block 1
- El campo `protocolo` del registro toma los valores `tcp`, `tls`, `udp` y `xhr`. — supuesto del implementador, aceptado por las dos revisiones; mostrado al usuario — 2026-11-10 — Block 1
